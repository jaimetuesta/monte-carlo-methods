## Overview

A study of Monte Carlo integration, following a guided assignment of 24 exercises. The project implements the methods in Python and analyses them experimentally:

- the basic Monte Carlo estimator (the integral as an expected value) and its run-to-run variability,
- its convergence rate, checked empirically against the theoretical O(n^-1/2),
- hit-or-miss (acceptance–rejection) integration,
- importance sampling as a variance-reduction technique,
- comparison with deterministic rules (rectangle rule) in 1D and 2D,
- integration over non-rectangular domains and in high dimension (up to d = 10), and the curse of dimensionality.

### Reproducibility and the random seed

The notebook fixes the random seed (`np.random.seed(0)` in the first code cell), so running it from top to bottom reproduces the stored outputs and the numbers in the report. The results depend on the seed: with a different seed, or when cells are run out of order, the numerical values change slightly (this is the expected behaviour of a stochastic method), while the conclusions remain the same. The execution times in exercise 24 also depend on the machine.

## Main results

All values below come from the stored notebook run (seed 0).

- **Convergence:** the error of the basic estimator decreases as O(n^-1/2); the empirical slope on the π example is −0.48.
- **Deterministic rules in 1D:** for eˣ on [0,1], the rectangle rule converges as O(n^-1) and is far more accurate than Monte Carlo for the same number of evaluations.
- **Importance sampling:** with a proposal proportional to the integrand (narrow Gaussian peak), the estimator has zero variance. For 1/(1+x⁶) on [−3,3], a Gaussian proposal with σ² = 1 reduces the mean error from 0.0073 (uniform) to 0.0024; narrower or wider proposals reduce it less.
- **2D on the unit disc:** the rectangle rule no longer reaches O(n^-1) because of the curved boundary (fitted slope −0.69, non-monotonic error), while Monte Carlo keeps a slope close to −0.5 (−0.49).
- **High dimension:** a regular grid with 10 nodes per axis needs 10^d evaluations (10^10 for d = 10), while Monte Carlo keeps a fixed budget. The order n^-1/2 does not depend on d, but the constant does: for the test integrand, the standard deviation of the estimate grows from 0.0004 (d = 1) to 0.05 (d = 10) with the same n.
